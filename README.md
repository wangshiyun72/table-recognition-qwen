# 复杂表格识别与内容理解：基于千问多模态大模型的解决方案

> Complex table recognition & understanding with Qwen multimodal LLMs — a full pipeline for the Tianchi
> “知乎知学堂大模型挑战赛”: PDF/image rendering → task-specific prompting → robust answer normalization →
> multi-model ensembling. Best score **80.5 / 100** (season 2).

本仓库是天池 **「知乎知学堂大模型挑战赛：大模型复杂表格识别与内容理解」** 的参赛代码。
比赛要求只使用阿里云千问系列模型（通过百炼 API 调用），从 PDF / 图片里的复杂表格中完成结构恢复、内容提取和推理计算三类题目。

## 成绩

| 版本 | 分数 | 主要改动 |
|---|---|---|
| v1 | 70.5 | qwen3-vl-plus 基线：分题型提示词 + 答案清洗 + 结构题程序截取 |
| v2 | 71.9 | 模板题（语言、标题、左右表头、“是否”题）统一作答约定 |
| v3 | 80.1 | 换用 qwen3.7-plus / qwen3.8-max（思考模式）；修正小数逗号等清洗问题 |
| v4 | **80.5** | 三模型投票：两个主模型答案不一致时由第三个模型裁决 |

评分方式为 `正确题数 / 总题数 × 100`，每题完全正确才得分。

## 任务与数据

数据在 `multimodal_table_recognition/` 目录下（经主办方确认可公开）：

- `files/`：90 个文件，包括 PDF（含扫描件、旋转页、跨页表）和 jpg / png / webp 图片，内容涵盖财务报表、学术论文表格、发票、报关单、课程表、合并单元格示例等；
- `tests.xlsx`：908 道题；
- `submit-template.xlsx`：提交模板。

| 题型 | 题数 | 说明 |
|---|---|---|
| extract（内容提取） | 653 | 按行列标题、多级表头定位单元格、行、列或区域 |
| thinking（内容推理） | 216 | 先定位数据，再求和、求差、比例、筛选、排序、计数 |
| structure（结构恢复） | 39 | 输出 `row_count / col_count / cells`（含 rowspan、colspan），常要求只恢复“第一行”“前 N 列”“表头行” |

答案格式分为 `string`（396 题）、`number`（365 题）、`json_array`（107 题）和 `json`（40 题）。

## 方法

```
文件 ──► 渲染（PDF→图片 + 文字层） ──► 分题型提示词 ──► 千问 VL 模型 ──► 解析与清洗 ──► 校验 ──► submission.xlsx
                                         ▲                    │
                                 模板题专用约定           缓存 / 重试 / 多模型轮换
```

### 1. 数据修正（`tablebot/data.py`）
- 题目清单本身有几处错误，由程序自动修正：id=63 的 `question_type` 列填成了题目文本，按内容推断为 extract；`58.pdf`、`0060.pdf` 等文件名与实际文件不一致，按编号匹配。

### 2. 渲染（`tablebot/render.py`）
- PDF 用 pypdfium2 渲染。有文字层的按 180 dpi 渲染，**扫描件提高到约 250 dpi**（小字号的数字最容易看错），旋转页会自动转正。
- 有文字层的 PDF，把抽取出的文字一起发给模型，用来核对数字和文字。
- 图片统一处理：转成 RGB（透明背景铺白）、按 EXIF 信息转正、太小的图放大、太大的图缩小。
- pdfium 不是线程安全的，并发读 PDF 会导致进程直接崩溃（Windows 上没有任何报错），因此所有 pdfium 调用都放在一把全局锁里。

### 3. 提示词（`tablebot/prompts.py`）
- **三类题各用一套任务说明**，统一要求模型输出 JSON：
  - 提取题：`{"location", "answer"}`；
  - 推理题：`{"evidence", "expression", "answer"}`，模型写出的算式由程序重新计算，用来纠正心算错误；
  - 结构题：输出**整张表**的紧凑单元格数组 `[行, 列, 跨行, 跨列, 文本]`，外加 `header_rows`（表头行数）。
- **模板题专用约定**：数据中有大量模板化题目（表格语言、主表标题、最左/最右表头、列数、“是否……”、多字段数组），每类题都附加一条明确的作答约定，保证同类题答法一致。

### 4. 结构题：模型只负责识别整表，范围由程序截取
模型自己判断“只恢复第一行和前 3 列”这类范围时很不可靠，会漏掉第一列，或把数据行当成表头。现在的做法是：
1. 模型只负责输出整张表的结构；
2. 程序解析题目文字（前 N 行、第 N 列、表头行、整个表格，支持中文数字），按范围截取单元格；
3. 程序修复常见错误：表头行被重复输出时删除重复行；合并单元格的跨度估大、和其他单元格重叠时，缩小跨度；行列数按单元格实际占用的范围校正。

### 5. 答案清洗（`tablebot/normalize.py`）
评分是全对或全错，清洗对分数影响很大：
- **区分千分位和小数逗号**：`1,234,567.89` → `1234567.89`，`9,4`（欧洲写法）→ `9.4`；
- 用 `Decimal` 解析 JSON，保留表格里显示的小数位（`32239502.30` 不会变成 `32239502.3`）；
- 会计负数 `(100)` → `-100`；`5045(33.1)` 取括号前的主数值；
- “是否”题统一答“是”或“否”（包括数组里的元素，不写 true/false）；
- 语言名统一成中文（`English` → `英文`，中英混排 → `中文和英文`）；
- 推理题：程序计算模型写出的算式，结果与模型答案不一致时，以算式结果为准，并沿用模型答案的小数位和百分号格式；
- JSON 不完整时单独提取 `answer` 字段；仍然失败，或答案为空时，带着提示让模型再答一次。

### 6. 工程上的稳健性（`tablebot/llm.py`、`tablebot/pipeline.py`）
- **磁盘缓存**：以模型 + 完整提示词的哈希为键，重跑、断点续跑都不会重复付费；
- **按模型分目录保存结果**，可以用 `--fallback` 拿其他模型的结果补缺，用 `--refinalize` 只重新清洗、不调用 API；
- **多模型轮换**：百炼给每个模型单独的免费额度，开启“免费额度用完即停”后，一个模型额度用完会自动换下一个；
- 遇到欠费、Key 无效等账户问题立即停止，不再发送注定失败的请求；
- 提交前自检：检查行数、题号、空单元格、JSON 格式（评测系统不接受空单元格）。

### 7. 多模型投票（`scripts/ensemble.py`）
两个主模型的答案不一致时，看第三个模型和谁一致就取谁；三者都不同时，取最强的模型。v4 就是用这种方法从 80.1 提到 80.5。

### 试过但效果有限的方法
- **同一模型多次采样投票**（`--votes 3`）：答案稳定性略有提升，费用约 3 倍，提分不明显；
- **列数题让模型先逐列列出列名再计数**：模型多用占位符敷衍，结果和直接计数几乎一样。

## 项目结构

```
├─ run.py                     # 唯一入口（命令行）
├─ tablebot/
│   ├─ config.py              # 默认配置：模型、分辨率、并发、清洗选项
│   ├─ data.py                # 读题、修正数据问题、文件名匹配
│   ├─ render.py              # PDF / 图片 → 页面图片 + PDF 文字层
│   ├─ prompts.py             # 各题型提示词 + 模板题约定
│   ├─ llm.py                 # 百炼 OpenAI 兼容接口：流式、重试、缓存、多模型轮换
│   ├─ normalize.py           # JSON 解析、答案清洗、结构题截取与修复、算式复核
│   └─ pipeline.py            # 并发调度、结果保存、提交文件生成与自检
├─ scripts/ensemble.py        # 三模型投票合并
├─ multimodal_table_recognition/   # 比赛数据（files/、tests.xlsx）
├─ requirements.txt
└─ .env.example               # 复制为 .env 并填入 API Key
```

运行后会生成 `work/`（缓存和每题结果）和 `outputs/`（提交文件），这两个目录不纳入版本管理。

## 快速开始

```bash
pip install -r requirements.txt
cp .env.example .env          # Windows：copy .env.example .env
# 编辑 .env，填入百炼 API Key：DASHSCOPE_API_KEY=sk-xxx

python run.py --check                        # 检查数据与 API
python run.py --dry-run                      # 只渲染和拼提示词，并估算 token 用量
python run.py --limit 20                     # 试跑 20 题
python run.py --models qwen3.8-max --thinking   # 全量运行，结束后自动生成 outputs/submission.xlsx
```

常用参数：

| 命令 | 作用 |
|---|---|
| `--ids 1-50,63` / `--file 006.pdf` / `--types structure` | 只跑部分题目 |
| `--only-missing` | 只跑还没有成功结果的题（断点续跑） |
| `--models a,b,c` | 多模型轮换，前一个免费额度用完自动换下一个 |
| `--thinking` | 开启思考模式 |
| `--votes 3` | 同一模型采样 3 次投票 |
| `--show 32` | 查看某题的提示词、模型原始输出和最终答案 |
| `--refinalize` | 改了清洗规则后，不调用 API，重新生成答案和提交文件 |
| `--submit-only --fallback qwen3-vl-plus` | 用已有结果生成提交文件，缺的题用其他模型补 |
| `--list-results` | 查看各模型已有多少题的结果 |

## 费用参考

全量 908 题大约需要 400 万输入 token。qwen3-vl-plus 不开思考模式只要几块钱；qwen3.8-max 开思考模式约 100 元。可以先用各模型的新人免费额度，配合 `--models` 轮换使用。
